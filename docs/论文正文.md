# 摘要与设计目标


针对葡萄疏果中的可见果粒计数与小果筛选需求，本文设计基于YOLOv8n的检测与相对尺度筛选原型。花序分支输出整花序与小穗位置，果粒分支结合单穗ROI、尺度规则和可见保留上限生成编号图及CSV、JSON记录，供人工复查。


主实验中，辅助果粒120个测试图块的F1为0.7467，整花序和小穗在79张测试图上的F1分别为0.8865和0.5626；补充三个训练种子后，辅助果粒F1为0.7493±0.0015。整花序定位较稳定，小穗及稠密果粒的漏检仍是主要误差来源。幼果适配在2个测试区域上完成流程试验，F1为0.8800、MAE为3.00粒/区域。幼果标签未经专家复核，桌面交互尚未验收，当前交付依据命令行流程与可复查输出评价。


关键词：阳光玫瑰；疏果；YOLOv8；可见果粒计数；相对尺度


# 1 研究背景与任务要求


传统颜色和形状方法容易把绿色叶片、果梗与幼果混淆。Mask-GK采用实例掩膜高斯核进行果粒分割计数[1]；MVDNet结合计数与果穗分割研究疏果期计数[2]。本文选择具有现成预训练权重和检测工具链的YOLOv8n[3]，将课程设计工作集中在数据处理、检测与筛选规则的衔接和输出核查。CPU训练条件及现有框标签使这一方案便于实施；未开展检测器横向比较，模型选型依据是实现条件，而非已证明其优于实例分割。


疏果效果受品种、生育期及环境条件影响[9]。公开精品果指标中，马陆阳光玫瑰为45—50粒每串[4]，对应整穗生产目标。本文处理的是二维照片中可见对象的相对大小，保留上限由操作者根据ROI设定。网页栽培记录[5]用于图像来源与任务背景，尺度规则的农艺适用性在第8节讨论。

# 3 算法结构与设计程序


![图4 检测 筛选及结果导出的功能关系](figures/system_design.png)


输入图像先由用户框选单穗。大区域使用1024像素窗口和768像素步长，坐标回到原图后以NMS消除重复框。模型输入固定填充到384像素，避免单图与批量填充方式不同造成计数差异。花序分支用于定位整花序、统计小穗及保存框坐标，不自动决定疏花或疏小穗；其计数不换算成果粒数，也不与果粒去除动作相加。果粒分支才继续执行尺度筛选。


绝对像素大小随拍摄距离和成像比例变化，因而以当前ROI内检测框的中位尺度作归一化。第i个框宽高为wᵢ、hᵢ，投影尺度dᵢ=√(wᵢhᵢ)，相对尺度rᵢ=dᵢ/median(d)。当rᵢ<τ时建议去除。τ=0.70为可调的默认操作点，表7检查0.50至0.90范围内的规则响应；该值未经农艺目标优化。rᵢ表示二维相对投影尺度，尺度基准对选择性漏检的敏感性见7.1节。


保留上限K用于把操作者给定的可见目标转化为数量约束。在大小筛选后，从中心距离除以平均尺度最小的一对中优先去除较小者，迭代至保留数不超过K。N_total=N_keep+N_remove分别对应检测总数、保留数和建议去除数。逐粒编号、位置、尺度与原因共同保存，便于检查规则是否按预期执行。

# 7 阈值响应与失败样例


![图19 独立测试中计数误差最大的两个辅助果粒图块 青色标签 橙色预测](figures/test_error_examples.png)

# 8 结论与局限


本文贯通了可见目标检测、尺度筛选、可见保留上限与结构化导出。整花序定位是当前较稳定的识别环节；小穗和稠密果粒仍有较大漏检，单纯调整尺度规则难以解决查数误差。幼果分支完成了适配与程序流程检查，但它是证据最薄弱的部分：训练仅37张、测试仅2个区域，标签未经双人或农艺专家复核。本文据此区分检测性能、规则响应和流程可执行性。


评价范围还受数据和验收条件约束。编号分组控制了同源图块跨划分，但缺少植株与果园身份，无法建立充分的场景独立性；bootstrap区间以当前标签、模型和分组假设为条件。二维检测框不覆盖隐藏果粒、病虫害、朝向和穗形等农艺因素，当前筛选仍需人工复查，尚无田间疏除或机械剪切真值。后续应优先扩充跨果园、跨光照的幼果独立样本并完成标签复核，再比较输入分辨率、检测后处理或实例分割方案，最后进行田间疏除验证。
